# ww-discord-auth

Tiny login server for "Sign in with Discord". Deploy on Render (free). See render.yaml.

Env vars (Render > Environment):
- DISCORD_CLIENT_SECRET - from discord.com/developers > your app > OAuth2 (the Application ID is read from Firebase: users/{DISCORD_APP_OWNER_KEY}/discord_signin_id, saved in Settings)
- FIREBASE_SERVICE_ACCOUNT - the whole service-account JSON for project entertainment-71888
  (Firebase console > Project settings > Service accounts > Generate new private key)
- STATE_SECRET - auto-generated by render.yaml
- PUBLIC_URL / ALLOWED_ORIGINS - preset in render.yaml

Discord app: OAuth2 > Redirects must contain  https://ww-discord-auth.onrender.com/callback
Firebase console: Authentication > Settings > Authorized domains is NOT needed (custom token, no popup).

## SMLC (Home Inventory)

`/login?app=smlc&next=<page>` signs people into the **SMLC** Firebase (smlc-fuel-monitor) instead, for the
Home Inventory app in the SMLC repo (`inventory/`). Same Discord app; matched by verified Discord e-mail.
Needs the SMLC service-account JSON in the Key Vault row `firebase_smlc_service_account`
(or env `SMLC_FIREBASE_SERVICE_ACCOUNT`). SMLC page origins are always allowed.

## Linking Discord to an existing account

Settings > Sign-in methods shows Google, Email & password and Discord as Connected or Link.
- `POST /link` (idToken + next): links Discord to the signed-in account, even if the Discord e-mail differs.
- `POST /unlink` (idToken): unlinks; refused if it would be the only sign-in method. Unlinking also turns off e-mail matching for that account until it is linked again.
- Writes (admin only): `discord_links/{discordId}` = uid and `auth_links/{uid}/discord`. Add the matching rules from `database.rules.json` (`auth_links` readable by its owner, `discord_links` closed).

## Discord server bridge (the "Discord" pill in the site messenger)

`bridge.js` lets signed-in site users who have Discord linked, and who are members of the bridged server, read and post in that server's text channels from the site messenger.

Setup, once:

1. Discord Developer Portal -> your application -> **Bot**: turn on **Message Content Intent**, then **Reset Token** and copy the token.
2. Save the token in Firebase at `user_secrets/{owner key}/discord_bot_token` (never in the repo).
3. Portal -> **OAuth2 -> URL Generator**: scope `bot`; permissions View Channels, Read Message History, Send Messages, Manage Webhooks. Open the generated link and add the bot to the server.
4. The server is picked by invite code: Firebase `discord_bridge/invite`, else env `DISCORD_BRIDGE_INVITE`.

Only channels the bot can read are shown, so hide a channel from the bot's role to keep it off the site. Posts from the site appear under the person's Discord name and avatar (via a "Pack Hub" webhook) and can never ping @everyone, roles or users.

## Buy Me a Coffee payments (bmc.js)
Everything that costs money is paid on Buy Me a Coffee (buymeacoffee.com/raykevin71b): the mobile game packs (Tile Survival: Starter $1.99, Supply Crate $4.99, Builder's Vault $9.99, Gem Pouch $2.99, Coal Cart $1.99, Overdrive $8; allies pay at most ALLY_CAP $5) and Werewolf passes (tiers.js). Buy Me a Coffee item links can be pasted into ITEM_LINKS (`pass_t{1|2|3}_{month|year|lifetime|founder}`).
1. The page calls POST /bmc/claim and gets a claim code (e.g. `WW-7KQ3M`), the price and the Buy Me a Coffee link.
2. The buyer pays that amount on Buy Me a Coffee and types the code in the message (the e-mail they gave is the backup match).
3. Buy Me a Coffee calls POST /bmc/webhook (Integrations → Webhooks, endpoint `https://ww-discord-auth.onrender.com/bmc/webhook`). The signature is checked with `bmc_webhook_secret` from the Key Vault (Keys sheet → Firebase user_secrets/{DISCORD_APP_OWNER_KEY}).
4. The claim is granted once (`purchases/bmc_{claim}` ledger), packs to `user/{CODE}/platform/mobile/game/survive3_shop/orders/BMC-...`, passes to `overlay_pro/{account}`. The page polls GET /bmc/claim/:id.
Every webhook is kept in Firestore `bmc_events`; payments that couldn't be matched go to `bmc_unmatched` to sort out by hand. Direct links to each item can be pasted into ITEM_LINKS in bmc.js.
